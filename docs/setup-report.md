# セットアップ実測レポート (フェーズ1) — 2026-11-23

ブランチ `setup/production-pipeline` での作業記録。実装: DSH / 監督: Muse。
今回の完了条件は「公開」ではなく、フェーズ1 の基盤 + 短いテスト音声でのパイプライン通過。

## 1. TTS 経路 (決定事項どおり Google Cloud TTS)

- 認証方式: この Mac の既存 gcloud ユーザー認証 + `X-Goog-User-Project` ヘッダ
  (クォータプロジェクト)。値そのものは本書に記載しない (認証情報の書き出し禁止)。
- 流用元の実績: eng-listening `tools/content/cloud_tts.py` (同方式で運用中、
  今月 8,473字/155リクエスト のカウンタ実績あり)。本リポジトリにも同方式の
  クライアント (`tools/audio/cloud_tts.py`) を整備した。
- 実物確認: 声一覧 API (`texttospeech.googleapis.com/v1/voices?languageCode=ja-JP`)
  が HTTP 200。ja-JP-Neural2 は **B (FEMALE) / C (MALE) / D (MALE) の実在3声のみ**。
  合成 API はオーディション用サンプル生成で実呼び出しし、12リクエストすべて成功
  (当リポジトリのカウンタ: 951字/12リクエスト、無料枠月100万字の 0.1% 未満)。
- Gemini TTS は呼んでいない (禁止事項)。クライアントは ja-JP-Neural2 以外の声を
  コードレベルで拒否する。

## 2. 声候補オーディション (最終決定は監督側の確認後)

同一テスト台本 (`content/audition/test_script.json`, 4ビート/約230字, Tech用語・数字・
英語固有名詞・難読語入り) で3声を生成。サンプル: `audio/audition/<voice>/full.wav`

| 候補 | 性別/F0中央値 | 話速中央値 | 音声尺 | 一貫性ゲート | 書き起こし一致率 (全体) | ビート別 |
|---|---|---|---|---|---|---|
| ja-JP-Neural2-B | 女 / 269.7 Hz | 6.10 字/秒 | 51.9秒 | PASS (外れ値0) | 0.8853 | 0.913 / 0.686 / 1.000 / 1.000 |
| ja-JP-Neural2-C | 男 / 147.9 Hz | 6.41 字/秒 | 49.8秒 | PASS (外れ値0) | 0.8841 | 0.913 / 0.686 / 1.000 / 0.992 |
| **ja-JP-Neural2-D** | 男 / 151.4 Hz | 6.29 字/秒 | 50.6秒 | PASS (外れ値0) | **0.8911** | 0.942 / 0.686 / 1.000 / 1.000 |

- 測定条件: ゲート閾値 F0偏差15% / 話速偏差25% (voice_config)。
  書き起こし照合: faster-whisper small (ja) 全件照合、ゲート 全体0.70 / ビート0.60。
- **推奨: ja-JP-Neural2-D**。理由: 書き起こし一致率が3候補中最高 (0.8911)、
  話速が中庸 (6.29字/秒 ≒ ニュース読みの標準帯)、ゲートの余裕も最大。
  3候補の測定値の差は小さく (一致率の差 0.007)、音色の好みで B (女性声) に
  切り替えても測定上の問題はない。**最終確定は監督側の耳確認の後**とする
  (voice_config の声は暫定として D を設定済み)。
- ビート2 (b01) の一致率 0.686 は3声共通 → 音声の誤読ではなく ASR 側の表記差
  (whisper がカタカナ読みを NVIDIA/ChatGPT/Google 等の英字表記へ変換する) が主因。
  アニメ側と同様「ASR一致率は回帰検知、固有名詞の実読みは検証済み辞書で担保」の
  役割分担。実際の音声では辞書どおりのカタカナ読みで発話されている
  (b02 など英字を含まないビートは全候補 1.000)。
  ※ テスト台本自体も日本語文で英字を減らす (台本側でカタカナ併記する) 改善余地あり。

## 3. 読み辞書

- verified 登録: **23語** (`tools/audio/pronunciation_dict.json`)。
  出典は語ごとに `pronunciation_sources.md` に記録 (日本語 Wikipedia 冒頭の
  カタカナ併記 / デジタル大辞泉・実用日本語表現辞典 (Weblio)、すべて 2026-11-23 実取得)。
- 未確認リスト: `pronunciation_unverified.md` — GPT (単独), 従量課金
  (kotobank 404 / goo 到達不可のため出典なし), Kubernetes 異読 (クバネテス/クーべネティス、
  採用は第一表記クバネティス)。**推測の読みは1語も登録していない。**
- 生成前監査: `pronunciation_audit.py` が台本の未登録語 (漢字連続 + 英字トークン) を
  洗い出す。テスト台本では未登録 0、置換19件。監査レポート:
  `audio/audition/pronunciation_audit_report.md`。

## 4. スモークテスト実測 (Apple M4 / faster-whisper small CPU)

| 工程 | コマンド | 実測時間 |
|---|---|---|
| 辞書監査 (dry-run) | `pronunciation_audit.py` | < 1秒 |
| 音声生成 (4ビート/1声) | `gen_audition.py` | 9.1〜10.3秒 (ビートあたり TTS 2.0〜2.7秒 + 変換) |
| 一貫性ゲート (4ビート) | `check_voice_consistency.py` | 0.6〜0.8秒 |
| 全文書き起こし照合 (4ビート) | `transcribe_check.py` | 8.8〜16.7秒 (初回はモデル準備で16.7秒、2回目以降 8.9秒) |
| 3声合計 | gen_audition + ゲート×3 + 照合×3 | 約65秒 (推論キャッシュ後) |

本番 (5分/約1,600字 ≒ ビート20〜30本) への外挿: 生成 約40〜60秒、ゲート 約3〜5秒、
書き起こし照合 約60〜90秒。**1日の製作工程の音声部分は数分以内に収まる見込み。**

## 6. 制限事項・次のアクション

- 声の最終確定は監督側の耳確認 (サンプル: `audio/audition/<voice>/full.wav`)。
  確定後、`voice_config.json` の `voices.narrator.voiceName` を確定値に更新する
  (ハッシュが変わり既存音声との混在防止が働くため、エピソード音声は全再生成となる)。
- ASR 一致率を上げる改良 (台本側のカタカナ併記、normalizer の英字対応) は今後の改善項目。
- Kubernetes の読み異読 (クバネテス/クーべネティス) は監督側の裁定待ち。
- main マージは本ブランチの実物検証 (監督側) の後に行う。
